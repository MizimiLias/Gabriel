# Gabriel Agent

Gabriel is a single-module LangChain agent exposed through FastAPI. It keeps
conversation state in PostgreSQL and exposes both JSON and Server-Sent Events
chat endpoints.

The service intentionally has no authentication in v1 and binds to loopback by
default. Do not expose it directly to the public internet.

## Requirements

- Python 3.14
- `uv`
- PostgreSQL with permission to create the `gabriel_db` database

## Setup

```bash
uv sync
createdb -h localhost -U postgres gabriel_db
uv run alembic upgrade head
```

Copy `.env.example` to `.env` and fill in the real database and API credentials.
The local `.env` file is ignored by Git.

Start the API:

```bash
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8086
```

OpenAPI documentation is available at <http://127.0.0.1:8086/docs> in
development.

## API

Send a JSON chat request:

```bash
curl -X POST http://127.0.0.1:8086/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","message":"My name is Ada."}'
```

Send a follow-up using the same `session_id` to use persisted conversation
memory. Stream a response with:

```bash
curl -N -X POST http://127.0.0.1:8086/api/chat/stream \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{"session_id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","message":"What is my name?"}'
```

List Web sessions, ordered by most recent activity:

```bash
curl http://127.0.0.1:8086/api/chat/sessions
```

Inspect sessions produced by a specific channel (for example, QQ groups):

```bash
curl 'http://127.0.0.1:8086/api/chat/sessions?source=qq_group'
```

Rename a session:

```bash
curl -X PATCH http://127.0.0.1:8086/api/chat/sessions/3fa85f64-5717-4562-b3fc-2c963f66afa6 \
  -H 'Content-Type: application/json' \
  -d '{"title":"Project planning"}'
```

Read history:

```bash
curl 'http://127.0.0.1:8086/api/chat/sessions/3fa85f64-5717-4562-b3fc-2c963f66afa6/messages?limit=50'
```

Delete a session and its messages:

```bash
curl -X DELETE \
  http://127.0.0.1:8086/api/chat/sessions/3fa85f64-5717-4562-b3fc-2c963f66afa6
```

Web sessions receive a concise title generated by the configured chat model
after the first successful exchange. Title generation falls back to the first
user message if the model call fails. Sessions from other channels (such as QQ)
have no title.

Health endpoints are `/health/live` and `/health/ready`.

## Personas

A persona is a named system prompt plus optional preset dialogue. Preset
dialogue is injected as few-shot context between the system prompt and the
persisted conversation history; it is never stored in `chat_messages`, never
appears in session history, and does not consume message sequence numbers.
Personas are read from PostgreSQL on every message, so edits take effect on the
next request.

There is no global system prompt. A session without a persona sends no system
message at all — only its persisted history and the new user message.

Manage personas:

```bash
curl -X POST http://127.0.0.1:8086/api/personas \
  -H 'Content-Type: application/json' \
  -d '{
    "name":"Gabriel",
    "description":"Default assistant",
    "system_prompt":"You are Gabriel, a helpful personal assistant.",
    "messages":[
      {"role":"user","content":"Who are you?"},
      {"role":"assistant","content":"I am Gabriel."}
    ]
  }'

curl http://127.0.0.1:8086/api/personas
curl http://127.0.0.1:8086/api/personas/<persona-id>
curl -X PATCH http://127.0.0.1:8086/api/personas/<persona-id> \
  -H 'Content-Type: application/json' -d '{"system_prompt":"You are Gabriel, briefly."}'
curl -X PUT http://127.0.0.1:8086/api/personas/<persona-id>/messages \
  -H 'Content-Type: application/json' -d '{"messages":[]}'
curl -X DELETE http://127.0.0.1:8086/api/personas/<persona-id>
```

A web session binds a persona on its first message:

```bash
curl -X POST http://127.0.0.1:8086/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"3fa85f64-5717-4562-b3fc-2c963f66afa6","message":"Hello","persona_id":"<persona-id>"}'
```

There is no API for switching a persona mid-session. Update the database
directly; the next message picks it up. This also works for QQ sessions:

```sql
UPDATE chat_sessions SET persona_id = '<persona-id>' WHERE session_id = '<session-id>';
```

Deleting a persona clears the reference (`ON DELETE SET NULL`) and the session
falls back to no system prompt. `GET /api/chat/sessions` reports `persona_id`
and `persona_name` for each session.

`DEFAULT_SYSTEM_PROMPT` and `CHAT_SYSTEM_PROMPT` no longer exist. After
upgrading, existing sessions have `persona_id = NULL`, so they stop receiving a
system prompt. The QQ group sender prefix (`username: message`) is not explained
to the model unless a persona whose system prompt describes it is bound.

## QQ official bot

Gabriel uses the official `qq-botpy` SDK in WebSocket mode. The process makes
an outbound connection to QQ, so no public callback URL or inbound port is
required. QQ private chats use one session per user; group chats share one
session per group. QQ sessions are stored in PostgreSQL but are hidden from the
default session-list response used by the Web UI.

Set the bot's AppID and AppSecret, then enable the connector:

```dotenv
QQ_BOT_ENABLED=true
QQ_BOT_APP_ID=your-app-id
QQ_BOT_APP_SECRET=your-app-secret
```

The values come from the QQ bot dashboard under Development Settings. Apply the
database migrations before starting the service:

```bash
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8086 --workers 1
```

`QQ_BOT_ENABLED=false` prevents the SDK client from being created. Changes to
the flag require a service restart. Keep exactly one Uvicorn worker while QQ is
enabled; multiple workers would create duplicate QQ WebSocket connections.

## Configuration

Environment variables are documented in `.env.example`. `RAG_ENABLED` is
`false` by default. Embedding and vector settings are validated only when RAG is
enabled; v1 does not call embeddings or create vector tables.

## Quality Checks

```bash
uv run ruff format --check .
uv run ruff check .
uv run mypy app
uv run pytest
```

Integration tests run only when `TEST_DATABASE_URL` is set to an async SQLAlchemy
URL such as `postgresql+asyncpg://postgres@localhost/gabriel_db_test`. The live
provider test is opt-in with `RUN_PROVIDER_TESTS=true`. Apply
`uv run alembic upgrade head` to the test database before running the
repository integration test.

## Deployment

`deploy/gabriel-agent.service` runs one Uvicorn worker, which is required for
the in-process per-session lock. Production environment values belong in
`/etc/default/gabriel-agent`; an example is provided in
`deploy/gabriel-agent.env.example`.
